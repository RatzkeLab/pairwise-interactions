**4× the reads changes nothing that matters for the ML headline.** The strain-fold partitions
are identical between arms (same 74 strains, same seed), so the per-fold comparison is paired:

- **Rank metrics do not move.** cv_strain Spearman Δ within ±0.014 for every model, no
  Wilcoxon p below 0.36.
- **cv_strain R² drops slightly** (−0.015 to −0.066; significant for xgboost_raw_ko p=0.015
  and ridge_pca p=0.041). This is the label, not the data: `log2((n1+0.5)/(n2+0.5))` of a
  one-sided well scales with depth (cap ≈7.3 at 40 reads, ≈9.4 at 170), so label variance
  rose 14.0 → 18.3 and the p90 |label| went 6.4 → 7.8 while the median stayed 2.38. The
  genome cannot predict how deeply a well was sequenced; R² pays for it, ranks do not. A
  depth-independent target (capped log-ratio, or relative abundance) would remove this.
- **cv_pair improves** (two_stage_xgboost R² +0.030, p=0.003). Cleaner labels help
  memorising per-strain strength, which is what cv_pair measures (TRAPS §2).

This agrees with the earlier read-depth finding for this model (the relative-abundance model
was flat from 10 to 39 reads/well): label noise was never the bottleneck. The noise ceiling
rising to 0.96 against a model at 0.31 says the same thing.

**Shuffled control: fine, but the module's version is a single draw.** The corrected arm's
g03 shows SHUFFLED cv_strain ρ ≈ +0.12. `cross_validate` seeds the shuffle with a fixed
`1000 + fold`, i.e. one permutation per fold. Rebuilt over 20 permutation seeds, the null is
ρ 0.02 ± 0.10 on both arms, so +0.12 is one draw from it, not leakage.

## Traps found on the way

- **Copied output folders poison the minimap2 scan.** `mapping_validation` cached the
  combined read FASTQ with no validity check, so the first corrected-arm run scanned the
  old demux's reads out of the copied `outputs/`. `scripts/mapping_validation.py` now
  rebuilds unless the cache matches the cohort's per-well read counts. Other files that came
  with the copy and are not regenerated by `run_all.py` (r07–r11, TabPFN, p04b) were moved
  to `*/stale_copied_from_20260710/`.
- **`relative_abundance.make_all_figures` reads r03**, so the notebook's cell order only
  worked because old outputs existed. `run_all.py` calls it last.
- **Plates 21–29 are odd but were never sequenced.** "Odd plates" is not the sequenced set;
  `config.SEQUENCED_PLATES` is.
